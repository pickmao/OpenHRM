# 员工整体评价

在“分析研判 → 员工整体评价”按姓名检索，必须选择花名册中的唯一人员 ID。系统以花名册为主档：账号还须有同名且当前主部门一致的唯一关联，才能纳入账号填报与纪实；干部履历只通过账号的干部主档外键读取。无法可靠关联的数据在预览中给出缺口说明。

资料预览汇总当前花名册和历次任职履历、年度研判、知事识人自评与个人测评、关闭后的匿名测评结果、关闭后的优秀干部推荐、纪实、通用网上填报及个人奖励。历史研判保留每年每职务最新文件版本；自评按年度、表单、当时职务保留最新提交；个人测评按年度、表单、职位和评价人去重后汇总。若同部门仍有同名人员，姓名加部门仍无法区分的研判记录不纳入；奖励导入仅在花名册姓名全局唯一时纳入。班子/支部整体评价不直接作为个人评价。

匿名测评只在活动关闭且达到最小有效样本数后纳入汇总分，绝不传单份答卷、评语或投票人身份。只有文档、没有结构化 `payload_json` 的 Excel/OnlyOffice 填报仅显示任务元数据，模型不能读取其正文。资料预览不发送外部服务；生成按钮要求勾选确认，后端验证预览摘要仍然最新后才调用 Qwen。生成结果只是待人工核对的草稿，不自动做晋升、处分、排名或其他人事决定。

授权码 `cadres:overall_review:view` 可跨栏目查看资料；`cadres:overall_review:generate` 允许将资料发送至 Qwen 生成草稿，生成时两者都要具备。超级管理员可使用。普通账号还受数据范围限制：ALL 可查看全部花名册，ORG_UNIT 仅可查看名称匹配的部门，SELF 不可使用此跨栏目功能。

在仓库根目录创建不受 Git 跟踪的 `.env`，写入 `QWEN_KEY=...`。`start-system.ps1` 会将其交给本地后端；生产 Docker Compose 也会映射为后端所需的 `DASHSCOPE_API_KEY`。也可直接在后端进程环境配置 `DASHSCOPE_API_KEY`。可选 `QWEN_MODEL`，默认 `qwen-plus`。使用阿里云百炼中国站兼容接口。API：`GET /api/overall-reviews/search/?name=...`，`GET /api/overall-reviews/<roster-id>/`，`POST /api/overall-reviews/<roster-id>/generate/`（JSON 包含 `digest` 和 `confirm_external_transfer: true`）。模型调用失败不会记录 API 密钥或请求正文，当前版本不持久化草稿。
